# 가상실험실 템플릿 개발 안내

동아 확정 샘플(실험관찰+가상실험실)과 같은 모양·흐름의 차시를 `index.html` 하나로 만드는 방법을 적는다.
기준 구현은 이 저장소의 `index.html`(달 관측소)이다. **화면 부품을 더하거나 바꾸면 이 문서의 표도 같이 고친다.**

관련 문서: 샘플 분석 `docs/톤앤매너_분석.md` / 내용 범위 `docs/교과서_대조.md` / 남은 일 `docs/로드맵.md`

## 1. 화면 틀

```
#intro        시작 화면(전체를 덮음)
#app
 ├ #top       머리: 로고, 차시 제목, [준비물][도움 영상][관찰 일지](.hdi, 그림 + 글자) [소리][처음으로]
 ├ #tabs      차례 띠: 활동 순서. 끝난 칸은 ✓, 가 본 칸만 눌러 이동
 ├ #main
 │  ├ #stagePanel   #stepBar(번호 칩 + 한 문장 안내) + #stage(무대)
 │  ├ #side         옆 기록: 질문, 고르기, 관찰 기록
 │  └ .full > .panel  무대 없이 가운데 판만 쓰는 단계(예상·정리·고르기·마무리)
 └ #nav       [이전] [다음]
#pop          팝업(뒤 화면 흐림)   #toast  아래 가운데 알림
```

- `body[data-mode]`가 `intro / stage / panel` 중 하나로 바뀌며 위 틀에서 보일 것을 정한다. 단계별 값은 `MODE` 표.
- 무대 `#stage` 안에만 3D·그리기·착륙선이 들어간다. 무대 밖은 항상 미색 바탕.
- 폭 820px 이하에서는 무대 아래로 옆 기록이 내려간다. 그래서 안내 문장에 "오른쪽", "왼쪽"을 쓰지 않는다.

## 3. 색·글꼴·모양

`index.html` 맨 위 `:root`에 모여 있다. 단원이 바뀌면 `--pri`, `--pri-d`, `--soft`, `--soft2`, `--line`, `--pink`만 바꾼다.

| 변수 | 값 | 쓰임 |
|---|---|---|
| `--pri` / `--pri-d` | #BC499B / #8E2F74 | 단원 색, 단추, 핵심어 / 단추 아래 그림자 |
| `--soft` `--soft2` `--line` | #F8EBF4 #FCF5FA #EBD5E4 | 띠·칸 바탕, 테두리 |
| `--key` | #FFE08A | 제목 밑줄, 켜진 탭의 작은 글씨 |
| `--ans` | #1E6FE0 | 학생이 채운 답 |
| `--ok` / `--warn` | #17955A / #E5622B | 알림 / 경고 |
| `--paper` / `--ink` / `--sub` | #FBF8F3 / #221E1F / #6D6E71 | 바탕 / 글자 / 흐린 글자 |
| `--fd` / `--fb` | 잘난체 / G마켓 산스 | 제목 / 본문 |

- 둥글기: 판 24px, 무대 칸 20px, 단추·칸 14px, 알약 999px
- 단추: `.btn`(자주), `.btn.line`(흰 바탕 테두리), `.btn.dark`(검정, 닫기·돌아가기). 손이 닿는 것은 높이 44px 이상
- 글자 크기는 `--fs-h / --fs-inst / --fs-body / --fs-sub` 네 단계만 쓴다

### 정렬 규칙
- 글꼴 파일의 세로 기준값은 운영체제마다 다르게 읽힌다(윈도우에서 G마켓 산스가 글자 크기의 약 10% 위로 올라감). `@font-face`에 `ascent-override`, `descent-override`, `line-gap-override`를 적어 고정한다. 값은 "한글·숫자 잉크의 가운데 = 줄 가운데"가 되게 잡은 것
- 글자와 아이콘·알약을 한 줄에 놓을 때는 `display:flex;align-items:center`. 글자 크기가 다른 것끼리 기준선을 맞출 때만 `baseline`
- 한글은 `word-break:keep-all`. 좁아지면 낱말 사이에서만 줄이 바뀐다. 한 줄이어야 하는 이름표는 `white-space:nowrap`
- 칸 여러 개를 나란히 놓을 때 `grid-template-columns:repeat(auto-fit,minmax(…,1fr))`로 두어 좁으면 한 줄로 내려가게 한다
- 사파리는 `ascent-override`를 지원하지 않는다. 아이패드에서는 제목 글꼴이 약간 위로 보일 수 있음(미확인)
- 고친 뒤 `node tools/check_align.js`로 잰다

## 4. 문구 규칙

- 지시: "~해 주세요." / 예상·정리: "~해 보세요." / 결과 알림: "~했어요." / 설명: "~이에요, ~해요."
- 안내 띠는 한 문장, 한 가지 행동. 눌러야 할 것이나 핵심어만 `<b>`
- 용어는 교과서 그대로. 새 문구는 `docs/교과서_대조.md`와 대조
- 위치 말("오른쪽에서")을 쓰지 않는다(좁은 화면에서 배치가 바뀜)
- 오답 안내는 답을 말하지 않고 다시 볼 곳을 가리킨다

## 5. 새 단계를 넣는 순서

1. `STAGES`(순서), `MODE`(틀), `TABS`(차례 띠 이름)에 단계 이름을 넣는다
2. 가운데 판 단계면 `<section class="full" id="이름"><div class="panel">…`을 `#main` 안에 만든다
3. `function s이름(){…}`을 쓰고 `go()` 끝의 표에 넣는다. 안에서 할 일:
   - 무대 단계: `fly()`로 시점, `V.free`·`V.minD/maxD`로 조작 범위, `setSide(html)`, `inst()`
   - 조작을 받으려면 `onTap=(x,y)=>…`, `onDrag=d=>…`, 매 장면 처리는 `frameHook=()=>…`
   - 다 했으면 `allow(true,'다음 단추 이름')`
4. 기록할 값은 `fresh()`에 기본값을 넣고 바꿀 때마다 `save()`. 일지에 나와야 하면 `journalHTML()`에 한 줄
5. `#reset`이 지울 값을 `$('#reset').onclick`에 더한다
6. `tools/check_flow.js`에 그 단계를 지나가는 줄을 넣는다

`go()`가 단계가 바뀔 때마다 조작·유도·칩·팝업 상태를 모두 지우므로, 단계 함수는 자기에게 필요한 것만 켠다.

## 6. 다른 차시로 옮길 때

- 바꿀 것: `PRED`, `SPOTS`, `NEAR`, `SITES`, `WHY`, `FACES`, `PREP`, 인트로 문구, `KEY`(저장 이름), 단원 색
- 3D가 필요 없으면 `#stage` 안에 SVG나 그림을 넣고 `tick()`의 달 부분을 뺀다. 틀과 부품은 그대로 쓸 수 있다
- 자산은 모두 저장소 안에. WebGL 텍스처·3D 자료는 `assets/*.js`에 base64로 넣는다(`file://`에서 열려야 함)
- 안전 수칙이 있는 차시는 샘플처럼 준비물 팝업 오른쪽에 안전 다짐 칸을 두고, 둘 다 끝나야 시작하게 한다

## 7. 확인

```
node tools/check_flow.js shots            # 1280x800
node tools/check_flow.js shots 1024 768   # 태블릿 가로
node tools/check_flow.js shots 760 1000   # 태블릿 세로
```

- 마지막 줄의 `errs []`가 비어 있어야 하고, 캡처를 눈으로 본다(겹침, 잘림, 안 보이는 단추)
- 이 스크립트는 가상 브라우저다. 실제 기기의 터치·소리·성능·인쇄는 따로 본다
- 볼 것: 한 화면에 눌러야 할 것이 하나만 강조되는가 / 안내 띠 문장이 지금 할 일과 맞는가 / 옆 기록이 길어질 때 다음 단추가 화면 밖으로 밀리지 않는가

## 8. 새 샘플을 받았을 때

1. html과 자산 폴더를 저장소 밖 임시 폴더에 풀고 가상 브라우저로 연다
2. 인트로 → 팝업 → 각 쪽 → 가상실험실 단계 순서로, 누르기 전·후 상태를 모두 캡처한다
3. `<style>`에서 색 변수, 글꼴, 둥글기, 글자 크기를 뽑는다
4. 2번 표에 없는 부품이 있으면 표에 줄을 더하고 넣을지 정한다
5. `docs/톤앤매너_분석.md`에 날짜와 함께 달라진 점을 적는다
