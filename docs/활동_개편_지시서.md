# 활동 개편 지시서 (2026-11-23 이상우 결정)

방향: "알려 준 곳을 누르고 고르기"를 "직접 찾아서 찍기"로 바꾼다. 학생은 달 사진을 찍는 관찰자이고, 찍은 사진이 정리와 일지의 재료가 된다. 새 단계를 늘리지 않고 지금 단계의 조작을 바꾼다. 40분 안에 들어와야 한다.

작업 전 `CLAUDE.md`의 내용 범위·동아 요청 사항·기술 제약과 `docs/교과서_대조.md`를 다시 읽을 것. 한 항목씩 끝내고 `tools/check_flow.js`, `tools/check_align.js`를 세 화면 크기로 돌린 뒤 다음으로.

## 바뀌는 흐름
| 단계 | 지금 | 바꾼 뒤 |
|---|---|---|
| 예상 | 그림 카드 고르기 | 그대로. 정리 화면에서 내 예상 카드와 내가 찍은 사진을 나란히 보여 줌 |
| 관찰 1 모양 | 달 누르기 → 끌어 돌리기 → 모양 고르기 | 망원경 맞추기 → 초점 맞추기 → 원판과 공 견주며 돌리기 → 모양 고르기 |
| 관찰 2 표면 | 반짝이는 6곳 누르고 보기 고르기 | 임무 4개를 하나씩 받아 직접 찾아 찍기 |
| 정리 | 빈칸에 낱말 고르기 | 낱말 고르기 + 문장마다 내가 찍은 사진 붙이기 |
| 창의 활동(필수) | 달 무늬에서 본 모양 | 그대로 |
| 더 해 보기(선택) | 착륙 지점 고르기 / 구덩이 만들기 | 착륙 지점 고르기 / **달 모형 빚기** (구덩이 만들기는 없앰) |

## 1. 관찰 2를 "찾아서 찍기"로
근거: 교과서 탐구 과정(달 사진 관찰, 조사), 실험관찰 도움말(밝고 어두운 차이, 움푹 파인 곳을 주의 깊게).

- 임무는 한 번에 하나. 순서 고정
  1. 어두운 곳을 찾아 찍어 보세요 → 찍은 뒤 "어두운 곳을 **달의 바다**라고 해요"
  2. 밝고 울퉁불퉁한 곳을 찾아 찍어 보세요
  3. 둥글게 움푹 파인 곳을 찾아 찍어 보세요 → 찍은 뒤 "**충돌 구덩이**라고 해요"
  4. [뒷면] 단추가 나타남 → 탐사선이 찍어 온 달의 뒷면에서 앞면과 다른 점을 찾아 찍기(지금의 뒷면 질문 유지)
- 조작: 달을 끌어 돌리고 [크게]로 다가감 → 무대 가운데의 사진기 틀에 찍고 싶은 곳을 맞춤 → [찍기]. 찍는 순간 셔터 효과와 소리, 사진이 옆 기록 칸으로 날아감
- 판정(틀 가운데 지점의 위도·경도로)
  - 어두운 곳·밝은 곳: 색 지도의 그 지점 주변 평균 밝기. 경계 구간은 어느 쪽으로도 인정
  - 충돌 구덩이: 큰 구덩이 목록(이름, 위도, 경도, 지름)을 20개 이상 만들어 틀 안에 하나라도 들어오면 인정. 목록의 좌표는 출처를 확인해 넣고 `README.md`에 적을 것
  - 앞면·뒷면: 경도로
- 맞지 않을 때 "틀렸어요"라고 하지 않음. "조금 더 어두운 곳을 찾아볼까요?"처럼 다음 행동을 안내
- 단계적 도움(동아 요청: 무엇을 눌러야 할지 모르는 화면 금지)
  - 임무 시작: 사진기 틀과 [찍기]만 보이고, 끌기 유도 표시
  - 20초 동안 못 찍거나 두 번 맞지 않으면: 알맞은 곳 한두 군데에 반짝임 표시
  - 다시 20초: 그곳으로 달을 돌려 줌
- 찍은 뒤: 지금의 [표면 가까이 내려가 보기] 지형 장면은 유지. 지형 조각이 있는 6곳 가운데 찍은 곳과 가장 가까운 곳으로 들어감(멀면 단추를 숨김)
- 지점 수는 6 → 4. 관찰 지점 사진(`tb_*.jpg`, `spot_*.jpg`)은 임무 뒤 설명 칸에서 "교과서 사진과 견주어 보기"로 씀
- 상태: `S.found`를 `S.shots`(임무별 사진 dataURL, 위도·경도)로 바꿈. 이어서 하기와 일지가 깨지지 않게 옮길 것. 사진은 320px 안팎 jpg로 줄여 저장(localStorage 용량)

## 2. 관찰 1에 망원경 맞추기와 초점
근거: 지도서 오개념 "달은 원 모양이다"(입체 모형 제시가 지도 방안), `docs/로드맵.md` 4번.

- 맞추기: 밤하늘에 작은 달. 둥근 접안렌즈 시야를 끌어 달이 가운데 오게 함
- 초점: 흐린 달. 초점 손잡이(가로 밀기)를 움직여 또렷해지는 지점에서 멈춤. 또렷해지면 다음 안내
- 원판과 공: 또렷해진 달 옆에 "달 사진"(납작한 원판, 같은 그림)을 나란히 놓고 함께 돌림. 원판은 옆에서 보면 선이 되고 공은 그대로 둥긂 → 모양 고르기(지금 문항 유지)
- 접안렌즈 테두리는 관찰 1에서만. 관찰 2부터는 지금의 무대 화면

## 3. 정리에 내 사진 붙이기
- 지금의 낱말 고르기는 유지(실험관찰 10쪽 문장 그대로)
- 낱말을 다 채우면 문장 옆에 사진 자리가 나타남. 내가 찍은 사진을 끌어다 놓거나 눌러서 붙임
  - "어두운 곳" ← 임무 1 사진, "울퉁불퉁한 면" ← 임무 2, "충돌 구덩이" ← 임무 3
- 맨 아래에 내 예상 카드와 내가 찍은 사진 한 장을 나란히: "내 예상과 같았나요?" (같았어요 / 달랐어요, 맞고 틀림 표시 없음)
- 더 생각해요(달의 바다)는 그대로

## 4. 구덩이 만들기를 달 모형 빚기로
근거: 지도서 122쪽 대체 활동 "달 모형 만들기"(목표: 달의 특징을 관찰하여 모형으로 표현. 색점토로 공을 만들고 그림 도구로 눌러 충돌 구덩이를 표현. 정리: 어떤 특징을 모형으로 나타내었는지 소개).

- 화면: 왼쪽에 민무늬 회색 공(내 달), 오른쪽에 실제 달. 둘 다 끌어서 돌림
- 도구 3개를 차례로 엶
  1. 누르기: 누른 자리에 둥근 구덩이가 파임(누르는 시간에 따라 조금 커짐)
  2. 칠하기: 어두운 색으로 달의 바다를 칠함
  3. 문지르기: 표면을 울퉁불퉁하게
  - 지우기, 처음부터
- 구현: 공의 UV에 그리는 방식. 색 캔버스 + 높이 캔버스(범프/변위)를 CanvasTexture로. 레이캐스트로 UV를 얻어 붓 자국을 찍음. 태블릿 성능을 보고 캔버스 크기(1024×512부터)와 공의 분할 수를 정할 것
- 마무리: "내 달에 나타낸 것"을 고름(충돌 구덩이 / 달의 바다 / 울퉁불퉁한 면, 여러 개) → 내 달 사진이 일지에 붙음. 평가나 점수 없음
- 범위: 구덩이가 생기는 까닭, 돌, 크기·빠르기 조절은 넣지 않음. 손으로 빚는 것만
- 없앨 것: `sActB`, `assets/rock.png`, 관련 문구·일지 항목(`S.bDone`, `S.bTxt`), `tools/check_flow.js`의 해당 단계

## 손대지 않는 것
- 달 무늬에서 본 모양(필수), 착륙 지점 고르기(선택), 스스로 평가, 관찰 일지의 틀
- 화면 틀·색·글꼴·문체(`docs/템플릿_개발안내.md`)

## 걸리는 점 (작업하며 판단, 넘으면 먼저 알릴 것)
- 직접 찾기는 누르기보다 오래 걸림. 관찰 2가 12분을 넘으면 임무 2와 3의 도움을 더 일찍 냄
- 밝기 판정은 경계에서 틀릴 수 있음. 경계 구간을 넓게 잡고, 판정 때문에 학생이 막히는 일이 없게 함
- 사진을 localStorage에 넣으면 용량이 참. 넘치면 사진 없이 위치만 저장하고 다시 그리는 방식으로

## 끝난 기준
- 관찰 2에서 반짝임 도움 없이도 임무 4개를 끝낼 수 있고, 도움이 필요한 학생도 1분 안에 다음으로 넘어감
- 정리 화면의 문장 세 개에 내 사진이 붙고 일지에 그대로 실림
- 달 모형 빚기에서 구덩이·바다·울퉁불퉁한 면을 모두 나타낼 수 있고 실제 달과 나란히 돌려 볼 수 있음
- 1280×800, 1024×768, 760×1000에서 `check_flow.js` 오류 없음, `check_align.js` 통과
- 인트로부터 마무리까지 필수 경로가 30분 안팎
